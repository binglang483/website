# 加壳脱壳

> Packing & Unpacking · 二进制的"穿衣服"与"脱衣服"

## 什么是壳

**壳 = 压缩/加密后的 PE 文件 + 解压 Loader**

```
原始程序 (PE)
    │
    ├── 加壳器 ──→ 壳 + 加密后的原始代码
    │
    └── 运行时 ──→ Loader 解密 → 跳到原始 OEP → 正常执行
```

## 加壳目的

| 目的 | 说明 |
|------|------|
| 🛡️ 保护 | 防止逆向分析、版权保护 |
| 🔒 授权验证 | 商业软件的 License 校验 |
| 🔐 加密 | 对抗静态分析 |
| 📦 压缩 | 减小文件体积 |
| 🎭 隐藏 | 恶意软件隐蔽真实意图 |

## 壳的分类

### 按技术复杂度

| 等级 | 类型 | 代表 |
|------|------|------|
| ⭐ | 简单压缩壳 | UPX, ASPack, PECompact |
| ⭐⭐ | 加密壳 | Themida, Enigma, VMProtect |
| ⭐⭐⭐ | 虚拟化壳 | VMProtect, Themida VM |
| ⭐⭐⭐⭐ | 高级保护 | Armadillo, MPRESS, FSG! |

### 按运行方式

```
壳的执行流程:
1. 运行 Loader (壳代码)
2. 分配内存 / 解开原始代码
3. 还原导入表 (IAT)
4. 恢复原始节区属性
5. 跳转到 OEP (原始入口点)
6. 原始程序开始执行
```

## 脱壳方法

### 方法一：单步跟踪法

适用于：**所有壳**（理论上都能脱）

```
步骤:
1. x64dbg 载入加壳程序
2. 在入口点 (Entry Point) 开始
3. F8 (Step Over) 单步跟踪
4. 每步看 EIP 指向的模块
5. 当 EIP 离开壳模块，进入原始程序 → OEP 找到了！
6. 在 OEP 处 Dump + Fix Import
```

### 方法二：ESP 平衡法

适用于：**POPAD/RETN 结尾的壳**（UPX、FSG 等）

```
原理:
- 壳开始时通常 PUSHAD 保存寄存器
- 壳结束时 POPAD 恢复寄存器
- 然后跳转到 OEP

步骤:
1. 运行程序，暂停在入口点
2. 观察 ESP 地址（比如 0x12FF84）
3. 单步 / 运行直到看到 ESP 变回原值
4. 下一个指令就是跳转 OEP
5. 在那里设断点运行，到达 OEP
```

### 方法三：内存 Dump 法

适用于：**运行时已经解密到内存**

```
步骤:
1. 运行加壳程序
2. 在 OEP 处暂停（用方法一/二到达）
3. 打开 x64dbg 的内存视图
4. 找到原始节区（通常是可读可执行）
5. 使用 Scylla 或 x64dbg Dump 功能
6. 选择 "fix dump" 自动修复
7. 生成脱壳后的 PE 文件
```

### 方法四：预写脱壳脚本

适合常见已知壳：

| 壳 | 脱壳工具 |
|----|----------|
| UPX | upx -d pack.exe |
| ASPack | AspackDie |
| PECompact | PECompact Unpacker |
| Themida | Themida2Unpacker |
| VMProtect | VMPDecrypt / VMPUnpack |

## 实战示例：UPX 脱壳

```bash
# 方法 1: UPX 官方工具 (最简单)
upx -d protected.exe -o unpacked.exe

# 方法 2: 手动脱壳
# 1. x64dbg 载入 protected.exe
# 2. 入口点 PUSHAD → 标志 UPX
# 3. 设硬件断点在栈顶
#    (UPX 会在 POPAD 恢复栈)
# 4. Run → 停在断点
# 5. F8 → POPAD, F8 → JMP (到 OEP)
# 6. 查看栈: POPAD 时 ESP 值
# 7. 跳转到 OEP
# 8. Dump → Fix Import → Save
```

## OEP 定位技巧

### 特征码搜索

```
常见 OEP 模式:
├── 程序启动标准栈帧
│   PUSH EBP
│   MOV EBP, ESP
│   SUB ESP, 0x40
│
├── C++ 启动
│   CALL [InitializeCriticalSection]
│
├── 动态链接恢复完成
│   调用的 API 不再是壳的 stub
│
└── 导入表完整调用
    能看到调用 WriteFile / CreateWindow 等正常 API
```

### 单模块跳转

在 x64dbg 中下断：

```
断点: jmp dword ptr [xxx]
或: 运行到 x64dbg 显示 "Return to main module"
```

## 导入表修复

脱壳后 IAT 可能损坏，需要修复：

### 手工修复

```
1. 观察壳调用 API 后的位置
2. 原始 IAT 位置被壳覆盖
3. 重新构建 IAT:
   - 分配一块内存放导入函数地址
   - PE Header → Data Directory → Import Table
   - 填好 IMAGE_IMPORT_DESCRIPTOR 数组
4. 重写 PE Header
```

### 自动工具

- **Scylla** — x64dbg 插件，一键修复
- **ImportREC** — 独立工具，先 OEP dump 再 fix
- **ImpREC64** — 64 位版本
- **PETools** — PE 编辑器

## 虚拟化保护脱壳

VMProtect / Themida VM 是最难脱的壳：

```
原理:
┌──────────────┐
│ 原始指令     │  → 转换成 VM 指令序列
└──────────────┘         ↓
                  ┌──────────┐
                  │ VM Handler│  解释执行 VM 指令
                  └──────────┘
                  
脱壳思路:
1. 跟踪 VM Dispatcher（核心循环）
2. 记录执行过的 VM 指令
3. 逆向 VM Handler → 还原原始指令
4. 重构原始代码
```

**工具**：VMPDecrypt2, VMPUnpacker, 定制化脚本
