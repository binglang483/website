## Web 漏洞详解

### SQL 注入

```sql
-- 原始查询
SELECT * FROM users WHERE id = '$id'

-- 恶意输入
$id = "1' OR '1'='1"
-- 结果: SELECT * FROM users WHERE id = '1' OR '1'='1'

-- 修复：使用预编译语句
$stmt = $pdo->prepare('SELECT * FROM users WHERE id = ?');
$stmt->execute([$id]);
```

**检测工具**：SQLMap, NoSQLMap

### XSS 跨站脚本

| 类型 | 说明 |
|------|------|
| 反射型 | URL 参数直接输出到页面 |
| 存储型 | 恶意代码存入数据库，其他用户访问时触发 |
| DOM 型 | 前端 JS 直接拼接 HTML |

**修复**：对所有用户输入进行 HTML 实体编码。

### CSRF 跨站请求伪造

**攻击流程**：
1. 用户登录 A 网站，获取 Cookie
2. 用户访问恶意 B 网站
3. B 网站发起对 A 的跨站请求（利用已登录的 Cookie）

**修复**：Token 验证、SameSite Cookie、Referer 检查。

### SSRF 服务器端请求伪造

```
# 正常请求
http://api.example.com/fetch?url=https://public.com/data

# SSRF 攻击
http://api.example.com/fetch?url=http://127.0.0.1:8080/admin
http://api.example.com/fetch?url=file:///etc/passwd
http://api.example.com/fetch?url=http://169.254.169.254/latest/meta-data/
```

**修复**：白名单 URL、禁用私有 IP 段访问。

## 系统层漏洞

### 类型混淆

```cpp
union {
  struct typeA { int kind; } a;
  struct typeB { int kind; void* vftable; } b;
} obj;
// 将 typeA 当作 typeB 使用 → 类型混淆
```

**CVE 实例**：Chrome V8、Windows Kernel、Linux eBPF

### 缓冲区溢出

```c
void vulnerable(char* input) {
  char buf[64];
  strcpy(buf, input); // input 超过 64 字节 → 溢出
}
```

**缓解措施**：
- ASLR（地址空间随机化）
- DEP/NX（数据执行保护）
- Stack Canary（栈金丝雀）
- PIE（位置无关可执行文件）
- SafeSEH

## 分析方法论

### 1. 漏洞发现

- **白盒**：源代码审计、SAST 工具（SonarQube, Semgrep）
- **黑盒**：模糊测试（AFL, libFuzzer）、渗透测试
- **灰盒**：API 文档 + 动态扫描

### 2. 漏洞验证

- PoC 编写
- 影响范围评估
- 可利用性分析

### 3. 漏洞修复

- 代码补丁
- 安全加固
- 回归测试

### 4. 披露

- CVE 编号申请
- 厂商通知
- 补丁发布
