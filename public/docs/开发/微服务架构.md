# 微服务架构

> 拆分 · 独立 · 可扩展 — 从单体到分布式系统

## 为什么选择微服务

| 维度 | 单体架构 | 微服务架构 |
|------|----------|------------|
| 部署 | 整体打包 | 独立部署、灵活扩缩 |
| 故障 | 一个崩全崩 | 故障范围有限 |
| 协作 | 易冲突 | 可并行开发 |
| 运维 | 简单 | 需治理 |

## 核心组件

- **服务注册发现**: Consul / Nacos
- **API 网关**: Kong / APISIX / Spring Cloud Gateway
- **配置中心**: Nacos / Apollo
- **熔断器**: Sentinel / Hystrix
- **链路追踪**: SkyWalking / Jaeger

## 通信模式

### HTTP/REST

简单通用，调试方便。

### gRPC

高性能二进制协议，自带接口定义。

```protobuf
service UserService {
  rpc GetUser(GetUserRequest) returns (User);
}
```

### 消息队列

异步解耦、削峰填谷：订单 → Kafka → 库存/积分/短信

## 分布式事务

- **2PC/3PC**: 强一致但复杂
- **TCC**: Try-Confirm-Cancel
- **最终一致性**: 消息队列 + 补偿机制

## 服务拆分策略

按 DDD 业务领域拆分：用户域 / 订单域 / 支付域 / 商品域，每个服务拥有独立数据库。

## Kubernetes 编排

Deployment + Service + HPA 实现弹性伸缩。
